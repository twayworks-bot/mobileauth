2. **개발자 등급(`developer` flag: 0 ~ 2) 도입 계획**:
   * Keycloak User Profile 스키마에 `developer` 속성 추가 (`0`: 일반 user, `1`: developer, `2`: dev-leader).
   * 부트스트랩 계정(`01055787363`)은 `manager = "2"`(super)와 함께 `developer = "2"`(dev-leader)로 기본 보호.
   * 인증 및 세션 검증(`/auth/api/verify-session`), 로그인 `require_role` 검증, 프로필 화면(`/auth/profile`), 최고 관리자용 사용자 관리 대시보드(`/auth/users`)에 `developer` 등급 조회/검증/변경 기능 반영.
3. **로컬 개발용 공개 인증앱 직접 호출(Direct Call / Callback 우회) 예외 API 및 보안 통제 계획**:
   * 로컬 앱(`localhost`)이 공개 인증 서버(`https://holyseeds.thewayworks.net/auth`)와 도메인이 달라 `auth_session` 쿠키가 자동 공유되지 않거나 인바운드 웹훅/콜백이 막히는 문제를 해결하기 위해 **2가지 로컬 개발 예외 연동 모드**를 제공:
     * **모드 A (브라우저 리다이렉트 시 일회용/세션 토큰 쿼리 전달 + Direct Verify Call)**: 로컬 앱이 `https://holyseeds.thewayworks.net/auth/login?redirect=http://localhost:5000/callback&dev_mode=1` 호출 시, 로그인된 사용자가 **개발자 등급(`developer >= 1`)** 이상인 경우에 한해 리다이렉트 URL 쿼리에 `?session_id=<UUID>&dev_token=<서명된단기토큰>`을 첨부하여 브라우저가 로컬 앱으로 전달하고, 로컬 앱 백엔드가 공개 인증앱의 `/auth/api/dev/verify-session` (또는 `/auth/api/verify-session?session_id=...`)을 직접 호출해 검증.
     * **모드 B (로컬 앱 -> 공개 인증앱 Direct Auth & Verify API)**: 브라우저 리다이렉트조차 사용할 수 없는 로컬 CLI/백엔드/SPA 테스트 환경을 위해, 로컬 앱이 공개 인증앱의 `POST /auth/api/dev/direct-auth` (또는 `POST /auth/api/dev/verify`)에 직접 인증 요청/세션 검증 요청을 보내 세션 정보를 즉시 반환받고 검증하는 예외 엔드포인트 제공.
   * **보안 통제 가이드**: `developer` 등급(`1` 또는 `2`) 필수 제한, `localhost`/`127.0.0.1` Redirect 화이트리스트 강제, HMAC 서명 기반 단기 토큰(TTL), 환경 변수(`ALLOW_LOCAL_DEV_AUTH`) On/Off 스위치 등 다중 방어선 제안.
